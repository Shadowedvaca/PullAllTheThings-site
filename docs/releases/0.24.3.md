# Pull All The Things 0.24.3

## Highlights

- Prepares an owner-selected release candidate with canonical delivery, testing,
  coverage, browser-validation, runtime-identity, and promotion controls.

## Fixes/Changes

- Uses root `VERSION` as the application version authority and reports version,
  environment, and commit identity through FastAPI and `/api/health`.
- Adds curated release records, validation, exact-SHA deployment evidence, and
  post-production GitHub Release publication.
- Defines repository-owned static, unit, integration, regression, migration,
  provider-boundary, coverage, automated UI/E2E, and deployed-smoke expectations.
- Establishes measured fail-closed floors of 37% overall statement coverage and
  72% changed-line coverage, with an owner-approved exception process for any
  decrease.
- Adds a Chromium journey for the public login-to-registration path and retains
  coverage and browser failure artifacts in pull-request validation.
- Requires automated regression protection for defect fixes and distinguishes
  automated browser evidence from Parent-timed human UI validation.
- Removes the documented hotfix path that permitted production promotion before
  exact-SHA Test evidence completed.
- Keeps Production repository-blocked pending the migration/recovery and
  GitHub/SSH/credential controls owned by issues #54 and #55.
- Replaces stateless 30-day authentication with approved database-backed,
  independently revocable sessions: 7 days for ordinary members and 12 hours
  for rank level 4 and above, with no automatic renewal.
- Revalidates active-user and current-rank state on every authenticated request,
  revokes sessions on security-sensitive account or privilege changes, uses POST
  logout, and rejects cross-origin unsafe cookie-authenticated requests.

## Deployment/Migrations

- Migration 0182 creates `common.auth_sessions` plus password, account-state,
  and rank-change revocation triggers. Existing stateless tokens do not have a
  persisted session identifier and become invalid after deployment; users must
  sign in again. Deployment workflows resolve and verify an exact commit.
- This is a release candidate record, not deployment evidence. Test and
  Production promotion remain separately gated.

## Rollback

- Before merge, revert the focused child commits from draft PR #56. After an
  authorized compatible release, redeploy the prior immutable validated tag and
  downgrade migration 0182 only after the prior application code is active.
  Authentication-session rows contain no user-owned content. Database recovery
  remains governed by issue #54 and the backup runbook.

## Known Limitations

- Production remains disabled until issues #54 and #55 implement and verify
  recovery, GitHub protection, strict SSH trust, and credential isolation.
- The exact-SHA Test provenance preflight is implemented but has not yet been
  executed by this delivery slice.
- Local child #59 coverage could not execute PostgreSQL-dependent tests or the
  container gates; hosted PR CI remains the required authority for those layers.
